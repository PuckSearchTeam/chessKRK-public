# Violations present in the naive engine

The project context is the same as for the clean engine (paper, Section 5.1): responsibilities ranked by
speed of change, **rules** ≻ **policy** ≻ **strategies** ≻ {**valuation**, **pieces**, **protocol**} ≻ **wiring**,
the three axes in braces being unordered and, by the optional decision, hidden from one another (the strategies
were ranked below the adapters on 2026-10-19, as Clean Architecture ranks use cases below adapters). In the naive
engine there is no port yet and no variant piece, so *policy* and *pieces* are declared empty and five axes have
entities.

Tagging of the naive code by axis (paper, Section 4.3): the package is tagged, everything inside inherits its
axis unless tagged otherwise, and a mixed container gets the axis of most of the entities in its scope (its stated
purpose on a tie). Every foreign entity, one whose tag differs from its container's axis, is one containment
violation (paper, Observation 1): SRP when the container is a class, CCP when it is the package.

Fourteen axis mismatches in three containers.

Clauses (paper, Section 5.5): generated by the ranking — hide strategies from rules and policy; hide valuation and
protocol from rules, policy and strategies; hide wiring from everything else — and, in the optional block, written

Findings 3 and 4 give the two ports of the clean engine (`EndgameOracle`, `ChooseMoveUseCase`); 1 and 2 become the
`domain`, `application`, `adapter.uci`, `adapter.tablebase` and `infrastructure` packages. The expected end state is
`After/`, the same functionality with the architecture of the engine at the repository root, on which
`CleanArchitectureTest` and the constraint file both hold (Puck: no violation, with or without the optional block).

## What is *not* a violation

- `Main.main` calling `Engine.bestMove` and `Engine.tablebase()`: *protocol* using *strategies*, an adapter using a
  use case, which the Dependency Rule allows (before 2026-10-19 the two axes were unordered and the optional block
  reported these two edges).
- `Tablebase` uses `Engine.legalMoves`, `Engine.isLegal`, … : *valuation* using **rules**, the slowest axis,
  which is hidden from nothing. Allowed. (It becomes `RetrogradeTablebase` → `Rules` in the clean version.)
- `Engine.setPosition` reporting an error through `Main.send`: both are **protocol**. Allowed.
- `Main.main` calling `Main.send`: same axis.

## Behaviour preservation

The refactoring must keep both black-box checks green after each step (see README): the exhaustive UCI audit
and the cutechess match against the clean engine.

## What Puck reports

Puck (`docs/puck-run.md` says how; the kept logs are in `docs/puck-results/naive/`, rerun on 2026-10-20) reports
**26** violated edges with the Dependency Rule alone, the clauses generated by the ranking: the fourteen containment
edges of findings 1 and 2 (`Axis mismatches: 14 (14 reported above by hide clauses, 0 here)`) and the twelve uses
of findings 3 (6), 4 (4) and 5 (2). With the optional block, the three unordered adapter axes hidden from one
another, it reports **29**: the three edges of finding 6. The test class is left out of the rules by
`friend tests of all;` (tests are neither *wiring* nor an axis; `tests` is a predefined set, the classes under the
test source roots). Finding 7, the cycle, is not an edge; it is read off findings 3, 6 and the permitted use of the
strategy by `Main.main`, by Proposition 1, which applies once the optional block makes the permitted relation acyclic.
Every violation line ends with the repair of Table 3 (`[SRP, CCP: …]`, `[OCP, DIP: …]`, `[OCP, DIP, between axes
kept apart: …]`).

Finding 4 was not in the inventory drawn by hand before the first run (2026-10-06): the tool found it.
